Find where a quantum computer breaks your cryptography.

Acxelin Readiness reads your code, configuration, certificates, images and live endpoints, ranks what to migrate first, and writes the cryptographic bill of materials your auditors and tools expect.

What it reads

One scan covers the places cryptography hides, not only the code.

Source code
Python, JavaScript, TypeScript, Java, Go, C and C++, Rust, C#, Swift, PHP, Ruby and shell: calls, imports, constants, algorithm names and the parameters passed in.
Configuration
YAML, JSON, TOML, nginx, Apache, sshd, Kubernetes and Terraform: the algorithm and cipher lists you actually deploy.
Keys and certificates
PEM and DER certificates, private keys, keystores, SSH keys and known hosts.
Containers and binaries
Images saved with docker save or as OCI archives, and compiled files that carry library versions and algorithm strings.
Dependencies
Package manifests and lockfiles of the common ecosystems.
Live endpoints
TLS servers (which key-exchange groups they accept, their certificate, a grade from A to F) and SSH servers (algorithm lists and host keys).
Network captures
Handshakes in .pcap and .pcapng files: what clients and servers really negotiated.

What you get

Every scan writes the same set of files to readiness-out/.

report.html
One self-contained page: every asset ranked from critical to ok, with the fix and the places it appears. A button downloads the migration plan as migration.csv.
cbom.json
A CycloneDX 1.6 cryptographic bill of materials, with relationships and evidence for every asset.
readiness.sarif
The same findings for code scanning in GitHub and other SARIF viewers.
findings.json
Every detection and the verdict on it: accepted, held back, rejected or suppressed, with the reason.
relationships.json
Which functions reach the cryptography, for the languages with call analysis.

Where it runs

In every pull request

Fail the build only on cryptography a change introduces, by comparing with the CBOM from the main branch.

acxelin-readiness scan . --baseline cbom.json --fail-on high

For an audit

Check against NIST IR 8547 and the NSA's CNSA 2.0 suite, and fail when a rule is already broken.

acxelin-readiness scan . \
  --policy nist-ir-8547 --policy cnsa-2.0 \
  --fail-on-policy

Across many systems

Merge the CBOMs of every system, including ones made by other tools, into one ranked inventory.

acxelin-readiness merge out-a out-b \
  --name "Example Bank"

What it does not claim

A scan cannot prove cryptography is absent. Code that builds algorithm names at run time, or loads them from outside the scanned files, can be missed.

It never changes your files and never sends them anywhere. It reports where cryptography sits and of what kind, never the key itself.
