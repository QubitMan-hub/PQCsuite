Set up Acxelin VPN

Gateways need Linux, and the gateway image has everything else. People's computers need the desktop app and WireGuard. The administrator's command line needs Python 3.11 to 3.14 and OpenSSL 3.5 or newer. Nothing contacts Acxelin Quantum.

  1. Check the release

    The release is one archive, acxelin-vpn-{{VERSION}}-wheelhouse.tar.gz, the desktop installers, a SHA256SUMS file and build attestations that say which workflow built them. Check them before you unpack or install anything:

    sha256sum -c SHA256SUMS --ignore-missing
gh attestation verify acxelin-vpn-{{VERSION}}-wheelhouse.tar.gz --owner QubitMan-hub
tar xzf acxelin-vpn-{{VERSION}}-wheelhouse.tar.gz
cd acxelin-vpn-{{VERSION}}-wheelhouse

    You should see OK after each file's name, and Verification succeeded. If either fails, do not install it.

  2. Install

    For the administrator, in the unpacked folder:

    sh install.sh

    On Windows, unblock the script once, then run it with signed-or-local scripts allowed for this one command:

    Unblock-File .\install.ps1
powershell -ExecutionPolicy RemoteSigned -File .\install.ps1

    It installs from the wheels in the folder, offline, then runs acxelin-vpn doctor. You should see each check and Start here with the next commands.

    What it changes
    A private Python environment in ~/.acxelin/vpn and the command ~/.local/bin/acxelin-vpn. On Windows, %LOCALAPPDATA%\Acxelin\vpn and %LOCALAPPDATA%\Acxelin\bin, which it adds to your user PATH.
    Gateways
    Pull ghcr.io/qubitman-hub/acxelin-vpn:{{VERSION}}, or install on the host with the systemd units in deploy/systemd; the manual has both.
    Remove it
    sh install.sh --uninstall, or install.ps1 -Uninstall. Your authority, certificates and settings stay where you put them.

  3. Create the authority and the gateways' certificates

    acxelin-vpn ca init --name "Acme VPN Root" --dir pki
acxelin-vpn ca issue site hq.acme.example --san 203.0.113.10 --dir pki --out pki/issued/hq
acxelin-vpn ca issue site branch1.acme.example --san 198.51.100.7 --dir pki --out pki/issued/branch1

    ca init asks for a passphrase and encrypts the authority's key with it. Each gateway gets its own folder, pki/ca.crt and pki/crl.pem; the authority's key stays where it is.

  4. Connect the two sites

    Put each site's configuration in /etc/acxelin-vpn/site.toml, starting from config/site-hq.toml and config/site-branch.toml, then on each gateway:

    docker run -d --name vpn --network host --cap-add NET_ADMIN \
  -v /etc/acxelin-vpn:/etc/acxelin-vpn:ro ghcr.io/qubitman-hub/acxelin-vpn:{{VERSION}}
docker exec vpn acxelin-vpn status --config /etc/acxelin-vpn/site.toml

    Open UDP 500 and 4500 between the gateways, and TCP 7443 to headquarters. An established tunnel is not proof on its own: send real traffic between the subnets and check the byte counters move.

  5. Start remote access

    Next to the authority, the enrollment service that invitations use; on the headquarters gateway, the WireGuard gateway with your pool, routes and DNS in /etc/acxelin-vpn/gateway.toml:

    acxelin-vpn ca issue server ca.acme.example --san ca.acme.example --dir pki --out pki/issued/enroll
acxelin-vpn ca serve --dir pki --cert pki/issued/enroll/chain.pem --key pki/issued/enroll/key.pem
    docker run -d --name wg --network host --cap-add NET_ADMIN -v /etc/acxelin-vpn:/etc/acxelin-vpn \
  ghcr.io/qubitman-hub/acxelin-vpn:{{VERSION}} gateway --config /etc/acxelin-vpn/gateway.toml

  6. Invite a person

    acxelin-vpn invite alice --dir pki --enroll https://ca.acme.example:9443 --gateway vpn.acme.example:7443

    Send alice.acxinvite through a channel you trust; it works once, within 24 hours. Alice installs the desktop app and WireGuard, opens the file, chooses a passphrase and presses Connect. The window says Protected.

  7. Open the console

    acxelin-vpn console

    Your browser opens already signed in. Add each gateway by its status address to see tunnels and who is connected; invite and revoke from the People tab. For a remote machine, forward port 8901 over SSH and run acxelin-vpn console link --port 8901 there.

  8. Keep it running

    Run acxelin-vpn ca maintain --dir pki every day; a gateway whose revocation list has expired refuses everyone. The release folder has a daily timer for it. Before a wide rollout, test sleep and wake, a Wi-Fi change, a gateway restart and a revocation on the computers you actually use, and read what Acxelin VPN defends against.
