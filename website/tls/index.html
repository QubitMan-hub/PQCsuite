Put post-quantum TLS in front of services that cannot change.

Acxelin TLS is an edge proxy and a certificate authority. A client that cannot do post-quantum key exchange is refused, and the service behind the edge keeps running exactly as it is.

Set up in three commandsSee it refuse a classical client

What you put it in front of

Traffic recorded today can be decrypted later by a quantum computer. The edge protects the connection without touching the service.

Any TCP service
A web application, PostgreSQL, pgvector, MQTT or anything else that listens on a port. The edge terminates post-quantum TLS and passes plain traffic on over the local network.
A client that cannot change
A legacy client on one machine reaches a remote edge through a local port. The edge originates post-quantum TLS on its behalf.
Mutual TLS
Require a client certificate from your own authority. A revoked client is refused as soon as the edge has the new revocation list.
A ready-made setup
acxelin-tls bundle nginx --host web.example.com writes the certificates, the edge configuration and a compose file for nginx, PostgreSQL, pgvector or MQTT.

Your own certificate authority

The certificates are ML-DSA, a post-quantum signature. You run the authority that issues them.

Issue, renew, revoke
From the console or the command line. A daily ca maintain renews what expires soon and re-signs the revocation list.
Enrol machines
Devices enrol with a one-time token over EST (RFC 7030). Standard ACME clients, such as certbot, obtain ML-DSA certificates over ACME (RFC 8555).
Keep the root offline
Run an issuing authority under a root that never touches the server. The key can live in AWS KMS or behind your own signing command, though neither has been run against real hardware here.

Three policies

PolicyWhat a connection may use
strict (default)Post-quantum key exchange and ML-DSA certificates only
transitionAlso classical clients while you migrate, with a classical fallback certificate for browsers
cnsa2NSA CNSA 2.0: ML-KEM-1024, ML-DSA-87 and AES-256 only

Where it runs

Docker

One image with OpenSSL 3.5 included.

docker build -f products/tls/deploy/Dockerfile -t acxelin-tls .

Kubernetes

A Helm chart for the authority, EST, ACME and edges, and a sidecar example for one pod.

helm lint products/tls/deploy/helm/acxelin-tls

systemd

A unit for the edge, and a unit with a daily timer for authority maintenance.

systemctl enable --now acxelin-tls-edge

What it does not claim

Browsers cannot verify ML-DSA certificates yet. For them, the transition policy serves a classical fallback certificate, and that connection is only as strong as classical TLS.

A revoked certificate works until the edge next fetches the revocation list, which an edge that follows one does every 60 seconds by default. The service behind the edge sees plain traffic, so keep it on loopback or a private network.
