Set up Acxelin TLS

It needs Python 3.11 to 3.14 and OpenSSL 3.5 or newer. You do not need another Acxelin product, and nothing contacts Acxelin Quantum.

  1. Check the release

    The release is one archive, acxelin-tls-{{VERSION}}-wheelhouse.tar.gz, with a SHA256SUMS file and a build attestation that says which workflow built it. Check both before you unpack it:

    sha256sum -c SHA256SUMS --ignore-missing
gh attestation verify acxelin-tls-{{VERSION}}-wheelhouse.tar.gz --owner QubitMan-hub
tar xzf acxelin-tls-{{VERSION}}-wheelhouse.tar.gz
cd acxelin-tls-{{VERSION}}-wheelhouse

    You should see OK after the archive's name, and Verification succeeded. If either fails, do not install it.

    On Windows, compare the hash by eye with the line in SHA256SUMS:

    (Get-FileHash .\acxelin-tls-{{VERSION}}-wheelhouse.tar.gz).Hash
tar -xzf .\acxelin-tls-{{VERSION}}-wheelhouse.tar.gz
cd .\acxelin-tls-{{VERSION}}-wheelhouse

  2. Install

    In the unpacked folder, or in products/tls of a checkout:

    sh install.sh

    On Windows, unblock the script once, then run it with signed-or-local scripts allowed for this one command:

    Unblock-File .\install.ps1
powershell -ExecutionPolicy RemoteSigned -File .\install.ps1

    It installs from the wheels in the folder, offline, then runs acxelin-tls doctor. You should see each check and Start here with the next commands.

    What it changes
    A private Python environment in ~/.acxelin/tls and the command ~/.local/bin/acxelin-tls. On Windows, %LOCALAPPDATA%\Acxelin\tls and %LOCALAPPDATA%\Acxelin\bin, which it adds to your user PATH. No administrator rights, nothing system-wide.
    OpenSSL 3.5
    It uses the system's when it is new enough, otherwise Homebrew's, or the folder in ACXELIN_OPENSSL. On Windows: choco install openssl, then run the installer again.
    Remove it
    sh install.sh --uninstall, or install.ps1 -Uninstall. Your authorities, certificates and settings stay where you put them.

  3. See it work

    acxelin-tls try

    A one-minute tour with nothing to set up. The demo shows its real output, frame by frame.

  4. Create the authority and a certificate

    Use the console (step 6), or the command line:

    acxelin-tls ca init --name "Example Root CA" --dir pki
acxelin-tls ca issue server web.example.com --dir pki --out web

    ca init asks for a passphrase and encrypts the authority's key with it. Keep pki readable by its owner only.

  5. Put the edge in front of a service

    acxelin-tls edge --listen 0.0.0.0:8443 --target 127.0.0.1:8080 \
  --cert web/chain.pem --key web/key.pem

    0.0.0.0 listens on every network interface. Open port 8443 in your firewall only to the clients that need it, and keep the service itself on 127.0.0.1 or a private network.

    Add --require-client-cert --ca pki/ca.crt --crl pki/crl.pem for mutual TLS. For several routes, write an edge.toml, check it with acxelin-tls doctor --config edge.toml, and run acxelin-tls edge --config edge.toml.

  6. Open the console

    acxelin-tls console

    Your browser opens already signed in. Create the authority, then issue and revoke certificates, add running edges to see their policy, test a connection, and read the health checks. The console keeps the passphrase in memory only, so it asks again after a restart.

    On a remote server

    The console listens only on the machine it runs on. Forward a port, then ask the running console for a fresh link:

    ssh -L 8900:127.0.0.1:8900 server
acxelin-tls console link --port 8900

    Run the second command in that SSH session and open the address it prints on your laptop.

    In Docker

    docker run -v acxelin-tls:/data -p 127.0.0.1:8900:8900 ghcr.io/qubitman-hub/acxelin-tls:{{VERSION}} console --container
docker exec -it NAME acxelin-tls console link

  7. Keep it running

    Run acxelin-tls ca maintain --dir pki every day; the release folder has systemd units and a daily timer for it. Before you go to production, read what Acxelin TLS defends against and the manual.
