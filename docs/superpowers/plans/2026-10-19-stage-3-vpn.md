# Stage 3: Acxelin VPN

Goal: `acxelin-vpn` installs, runs, is tested and documented on its own, from its own release folder, with nothing from
Acxelin TLS or Readiness. Network teams connect sites over post-quantum IPsec, and staff connect over post-quantum
WireGuard from the desktop app. Spec: "Acxelin VPN", "Product interfaces", "Console access and security", "CBOM contract".

Baseline on main (fb61c41), this machine: 78 VPN tests pass, 6 skip (real strongSwan and WireGuard in network
namespaces, a real tunnel, a desktop session). CI's `vpn`, `windows-vpn` and `macos` jobs run the six; they stay required.

## Rules for this stage

- Tests first for every task; every task ends green and committed. No test is deleted or weakened; moved tests keep their assertions.
- Wire compatibility: a gateway on 1.0 talks to one still on the suite's 0.4.3 during an upgrade. The key-agreement
  protocol (exporter label `EXPORTER-pqcsuite-ipsec-v1`, message format, PSK and PPK derivation) does not change in this stage.
  A test pins it: old and new code agree the same keys from the same session.
- Old names are still read through 1.x, with a warning: `pqcsuite_invite` and `.pqcinvite` invitations, `PQCSUITE_*`
  variables, `~/.pqcsuite`, the `PQCSUITE-KILLSWITCH` chain and `com.apple/pqcsuite` anchor (removed when found, so an
  upgrade never leaves two kill switches).
- The VPN fixes its own policy (X25519MLKEM768, SecP384r1MLKEM1024, ML-DSA, TLS 1.3 only) in `acxelin_vpn`; it no longer
  borrows Acxelin TLS's `strict`. The layout test already fails on any import of another product.

## Tasks

1. **Product skeleton and the move.** `products/vpn` with package `acxelin_vpn`: charon, controller, wireguard, platforms,
   join, app, desktop and the VPN's policy. Moved tests: `test_vpn`, `test_wireguard`, `test_vpn_platforms`, `test_vpn_app`,
   `test_vpn_desktop`. New tests: wire compatibility, old-name reading with warnings, kill-switch migration (old chain and
   anchor removed, new one installed, nothing leaks during the swap), no import of `pqcsuite`, `acxelin_tls` or `acxelin_readiness`.
2. **Commands.** `acxelin-vpn up | gateway | invite | join | app | desktop | connect | disconnect | install | uninstall |
   status | check | doctor | console | console link`, and the CA subset the VPN needs: `ca init | issue | revoke | crl |
   maintain | list | serve` (`ca serve` is the EST service invitations enroll against). Tests: every command's help and
   errors in words, and `invite` then `join` end to end with only Acxelin VPN installed.
3. **Administrator console** on the core console mechanism (one-time link, no cookies, loopback only):
   - Sites: each IPsec tunnel's state, algorithms, last key rotation, and the peer's certificate.
   - People: invite a person and download their invitation file; who is connected and since when; revoke a person and watch their session end.
   - Health: doctor's checks with their fixes.
   Tests: API journeys, Playwright journeys with axe in light, dark and phone width, and the shared console security tests
   (missing or wrong token, lockout, non-local bind, wrong Host or Origin).
4. **Inventory export.** `acxelin-vpn inventory --cbom`: tunnels, groups, ciphers, certificates and PSK/PPK presence (type
   and size, never a value) as CycloneDX 1.6. Tests: schema validation with 0 errors, byte-identical content on re-export,
   and a secret scan for every known PSK, PPK, token and passphrase as bytes, hex, base64 and PEM. A repository-level test
   (in `tools/tests`) imports it into Readiness, so neither product imports the other.
5. **Deploy and package.** systemd units (`acxelin-vpn-ipsec`, `acxelin-vpn-wireguard`, `strongswan-pqc`,
   `acxelin-vpn-ca-maintain.timer`); the gateway Docker image with OpenSSL 3.5 and strongSwan 6.1 (the Packer images are removed); the desktop app
   installers for Windows, macOS and Linux (`packaging/`); `install.sh` and `install.ps1`; the customer release folder with
   manual, licence and units. Tests: wheel install alone, offline from the release folder, `doctor` and `--help` from it.
6. **Docs.** README, a full manual in the same form as the other two (install, a gateway and a laptop in fifteen minutes,
   everyday tasks, the console, the app, production, troubleshooting, questions, limits), threat model, upgrade notes
   (`pqcsuite vpn ...` to `acxelin-vpn ...`), changelog.
7. **Website.** A `/vpn/` section: overview, how it works, set up, manual, demo and security, with journeys and axe; the
   home page gains the VPN.
8. **Leave the suite.** `pqcsuite` keeps only Vault until Stage 4. CI's `vpn`, `windows-vpn` and `macos` jobs move into
   `acxelin-vpn.yml`; the release workflow gains `vpn-v*` tags.
9. **Verify and report:** all three product suites, the real-tunnel jobs, and the desktop app on each platform in CI.

## Improvements (after the move is green; each on its own, tests first)

- **A. Session health in the app:** time since the last key rotation, and a plain warning when the gateway stops
  re-agreeing (today the app shows only connected or not).
- **B. Who-did-what log:** invitations issued, enrollments, revocations and kill-switch changes in an owner-only audit log,
  shown in the console's People page.
- **C. One key-agreement module for IPsec and WireGuard** (the spec's spike): one code path to review instead of two.
- **D. ML-DSA in IKE itself:** check whether strongSwan 6.1 can authenticate IKE with ML-DSA certificates; if it can, offer
  it as an option next to today's ML-DSA mutual TLS. A check first, not a promise.

## Owner decisions (19 October 2026)

- Plan approved. Improvements A, B, C and D are all in this stage, after the move is green.
- Packer cloud images are dropped: the gateway ships as Docker, systemd units and the installers.
