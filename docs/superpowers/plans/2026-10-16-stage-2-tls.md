# Stage 2: Acxelin TLS/mTLS + CA

Goal: `acxelin-tls` installs, runs, is tested and documented on its own, with a console for routine work and its own website section. Spec: revision 3, "Acxelin TLS", "Shared core", "Console access and security".

Tasks, each tests first, each ending green and committed:
1. **Core extraction.** `acxelin_core.pki` (CA, CRL, signers, EST protocol), `acxelin_core.tls` (contexts, caller-supplied `Policy`, no named policies), `acxelin_core.server` (`Server`, `Stats`, `Revocation`), `acxelin_core.https`. Old `pqcsuite` names alias them. Tests: CA lifecycle, signers, EST and server move to `core/tests`; new tests prove the mechanisms follow two different caller policies and that a CNSA-style certificate requirement comes from the policy, not from a name.
2. **TLS product.** `products/tls`: edge, bundles, ACME, policies, commands (`acxelin-tls edge|bundle|serve|connect|ca ...|try|doctor|status`), config example. Tests: moved regression tests, plus: no generated text names another product.
3. **Console.** Certificates (create the CA, issue, revoke, refresh the CRL), Edges (status, connection test), Health (doctor). API journeys, Playwright journeys with axe, the shared security tests.
4. **Docs and deploy.** README, manual, threat model, upgrade notes; Docker, Helm, Kubernetes sidecar, systemd units under `products/tls/deploy`. Wheel install test with the console launched from the wheel.
5. **Website.** `/tls/` section: overview, how it works, set up, demo, security; journeys and axe. Home page gains the TLS entry.
6. **Verify and report.**

Known carry-overs: deployment verification for Readiness (core `pki` verify_crl) becomes possible here; the TLS bundle text that names Readiness's old command is removed.
