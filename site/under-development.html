You cannot migrate what you have not found

The endpoint scan shows what your servers offer. Most cryptography lives deeper: a hash in a login module, a key size in a config file, an old OpenSSL inside a vendor binary. Wolf Pack reads all of it and hands you one list, in the CycloneDX format auditors and tools already accept.

  • Source code

    Python, Java and Kotlin, Go, JavaScript and TypeScript, C and C++, C# and Rust.

  • Configuration

    nginx, Apache, HAProxy, sshd, openssl.cnf, Spring properties, YAML, INI and TOML.

  • Keys and certificates

    Including private keys that were committed by mistake, and certificates that outlive 2030.

  • Binaries and JARs

    Algorithm constants, embedded OpenSSL and other library versions, JCA names in class files.

  • Dependencies

    Manifests for pip, npm, Maven, Gradle, Go, Cargo and NuGet, checked against what the code imports.

  • Live TLS and SSH

    What each server negotiates, including whether it accepts hybrid ML-KEM groups.

Why it is called a pack

Scanners that match names drown you in false alarms. Wolf Pack splits the work so that finding and deciding are separate jobs.

01 · scoutsFind everything

Each scout reads one kind of source and deliberately over-reports. Missing something is worse than a false lead.

02 · denCheck the evidence

Mentions in comments, documentation, log messages and deny-lists are rejected. What is held back stays in the audit trail with the reason.

03 · alphaDecide what matters

Ranks each finding by how exposed it is and how long the data must stay secret, and says what to replace it with.

What you get from a scan

  • cbom.jsonThe inventory, in CycloneDX 1.6 and checked against its official schema
  • report.htmlA report you can open offline and forward as it is
  • wolfpack.sarifFindings in GitHub code scanning and other SARIF tools
  • findings.jsonEverything, including what was rejected and why

In CI it can fail a build only on cryptography added since the last release, so an existing backlog does not block every merge.

  2. First checks on real projects

    Eleven open-source projects it had never seen, reviewed by hand. The mistakes found were fixed.

  3. Blind benchmark

    18 public repositories, labelled by people before any tool runs on them. This is under way now.

  4. Part of the Readiness assessment

    One report covering your code as well as your endpoints.

Known limits

  • Only Python is fully parsed. Other languages use rules, so names built at runtime and values passed between functions can be missed.
  • An algorithm found in a binary is built into it, which does not always mean it is used.
  • Container images and cloud key management settings are not scanned yet.
  • The year a quantum computer could break RSA is an assumption you set, 2035 by default, not a prediction.
