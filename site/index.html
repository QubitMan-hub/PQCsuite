Scored on 91 labelled (file, algorithm family) pairs in the development corpus. That corpus was written alongside the scanner, so these numbers show that each role is live. They are not a measure of real-world accuracy. That needs a blind, held-out benchmark, which is the next stage of the work. Propagation also recovers parameters such as RSA-1024 rather than RSA, which family-level scoring cannot see.

Against IBM CBOMkit

Both tools ran on six real open-source repositories. Results are compared as (file, algorithm family) pairs, only in the languages CBOMkit supports, with test files left out. Java projects were built first, as CBOMkit requires. Wolf Pack was fixed on what these repos exposed, so these are numbers after tuning on them; the untouched test is the held-out benchmark.

The 5 pairs only CBOMkit found

  • 5All CBOMkit false positives: Ed25519, Ed448, X448, SHA-512 and SHAKE256 reported on paramiko's ML-KEM key generation, where it also missed ML-KEM
  • 2Former Wolf Pack misses in jjwt, AES named through a constant in another file, now found by cross-file propagation
  • 3Former convention differences, HmacSHA256 counted with its hash, now agreed after the labelling convention was confirmed

The 138 pairs only Wolf Pack found

  • 104Algorithm names in registries, enums and negotiation lists. Whether declared support counts is a labelling decision the benchmark has to make
  • 34Direct calls or imports that CBOMkit does not model
  • 8Former false positives, SSH key-format lists in pyjwt and python-jose, now held back by the alpha's recognition check

Four more repos CBOMkit supports (mkcert, itsdangerous, patrickfav/bcrypt, SecureStore), checked after the fixes above: Wolf Pack found every algorithm pair CBOMkit found. CBOMkit's one extra pair was a random-number generator, which the labelling guide leaves out, and it missed mkcert's RSA and ECDSA key generation in Go.

A 40-repo stress test in seven languages ran without a crash and with valid CBOMs everywhere. After fixing what it exposed, CBOMkit found 69 pairs on the 22 repos in its languages, and Wolf Pack found all of them except 14 that the labelling guide excludes: random-number generators, MGF1, and hashes internal to Ed25519. Those repos are tuned on, so this shows breadth, not accuracy.

What gets scannedWolf PackCBOMkit-action

This is an agreement study on unlabelled repos, reviewed by one person, not blind. It is not a precision or recall result. CBOMkit analyses Java semantically, which is deeper than Wolf Pack's rules there. It found nothing in java-jwt even after a build, and python-rsa calls no library it models. IBM's separate CBOMkit-theia scans certificates and keys in container images and was not part of this test.

Start hunting

Python 3.11 or newer. The commands below are for PowerShell; on macOS and Linux use source .venv/bin/activate.

# set up once
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -e ".[dev]"

# hunt a repository, and optionally its live endpoints
wolfpack hunt C:\path\to\repo
wolfpack hunt C:\path\to\repo --tls api.example.com:443 --ssh bastion.example.com

# in CI: fail only on crypto added since main
wolfpack hunt . --baseline main-cbom.json --fail-on high

# leave a member of the pack out, or score every ablation
wolfpack hunt . --without den
wolfpack bench bench\corpus
