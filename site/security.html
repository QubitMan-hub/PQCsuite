Security and trust

Your keys and your data stay with you.

The suite runs on your own machines. Nothing is sent to Acxelin, nothing depends on a service we run, and we never hold a copy of your keys. This page is for the security team that has to sign that off.

On your side

What stays on your systems

Your data

No account, no telemetry, no licence server. The suite connects only to the systems you configure: your edges, your certificate authority, your gateways and the endpoints you ask it to scan. It contacts GitHub only when you ask it to check for a new release.

Your keys

Certificate, server and backup keys are made and kept on your systems: in files encrypted with a passphrase by default, or in your own AWS KMS or HSM. We cannot recover a lost key, so every Vault backup must also open with a second recovery key kept offline.

Your code

Repository scans read your code on the machine that runs them and never execute it. The suite's saved scan results leave out source snippets. The sample reports on this site are made from invented example code.

What listens on your network

The TLS edge, certificate enrollment (EST) and the revocation list publisher are meant to be reached by other machines, so they listen on every interface; narrow them with --listen and your firewall. The console and the ACME service stay on the machine they run on. pqcsuite doctor --config warns when a setting widens that.

  • CryptographyML-KEM, ML-DSA and SLH-DSA (FIPS 203, 204 and 205) through OpenSSL 3.5 and pyca/cryptography. The suite implements no algorithm itself.
  • Hybrid by defaultBy default every key exchange combines a classical algorithm with a post-quantum one, so both would have to be broken.
  • Fails closedA revoked certificate is refused at its next connection; a forged or expired revocation list refuses everyone rather than letting anyone through.

Before you install

Check what you download

Every file in a release, the installers included, is built by our public GitHub workflow and carries a signed record of that build. Anyone can check it, without trusting us or this website.

Confirm a file came from our build

With the GitHub command-line tool, run this next to the downloaded file. It confirms which repository and workflow built it, and that it has not changed since.

The container image ghcr.io/qubitman-hub/pqcsuite carries the same signed record.

gh attestation verify acxelin-vpn_0.4.3_amd64.deb \
  --repo QubitMan-hub/PQCsuite

Every release

What a release has passed

A release is published only when every one of these passed on its exact commit. That is all it claims: it passed these checks.

Correct

Unit tests on Windows, macOS and Linux; the whole suite against real nginx, PostgreSQL, Redis, MQTT and SSH; the website and console in a browser with accessibility checks.

Secure

Known vulnerabilities in every dependency, a container image scan, CodeQL code analysis, and no new high-risk cryptography in the suite's own code.

Operational

A Kubernetes install serving a post-quantum request; IPsec and WireGuard tunnels with real traffic, revocation and the kill switch; a real VPN tunnel on Windows and macOS.

Then, every week

A two-hour load and revocation run, and a fresh install from the public download links, the way a customer installs.

Honest limits

What has not been validated yet

We would rather you hear these from us. Each one is in every release's readiness record until it is done.

AreaStatus
Independent security reviewNot done. The suite's own protocol code (the VPN key agreement, the Vault format, the TLS bridge) has had no outside review.
FIPS 140-3Not validated. The algorithms are the FIPS 203, 204 and 205 standards, but the product has not been through FIPS 140-3 validation.
Code-signed installersNot yet. Every file carries the signed build record above; Windows and macOS still warn on first launch.
Cloud and managed KubernetesThe AWS, Azure and Google Cloud images and the Helm chart are tested in CI and a local cluster, not yet in a customer's cloud account.
LaptopsFull tunnel, the kill switch and recovery are tested with real traffic on Linux; on Windows and macOS they have not been run on real laptops yet. Phones are not supported.
