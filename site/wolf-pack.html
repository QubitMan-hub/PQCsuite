What it reads

You cannot migrate what you have not found

An endpoint scan shows what your servers offer. Most cryptography lives deeper: a hash in a login module, a key size in a config file, an old OpenSSL inside a vendor binary. Wolf Pack reads all of it and hands you one list, in the CycloneDX format auditors and tools already accept.

  • Source code

    Python, Java and Kotlin, Go, JavaScript and TypeScript, C and C++, C# and Rust.

  • Configuration

    nginx, Apache, HAProxy, sshd, openssl.cnf, Spring properties, YAML, INI and TOML.

  • Keys and certificates

    Including private keys that were committed by mistake, and certificates that outlive 2030.

  • Binaries and JARs

    Algorithm constants, embedded OpenSSL and other library versions, JCA names in class files.

  • Dependencies

    Manifests for pip, npm, Maven, Gradle, Go, Cargo and NuGet, checked against what the code imports.

  • Live TLS and SSH

    What each server negotiates, including whether it accepts hybrid ML-KEM groups.

How it decides

Why it is called a pack

Scanners that match names drown you in false alarms. Wolf Pack splits the work so that finding and deciding are separate jobs.

01 · scoutsFind everything

Each scout reads one kind of source and deliberately over-reports. Missing something is worse than a false lead.

02 · denCheck the evidence

Mentions in comments, documentation, log messages and deny-lists are rejected. What is held back stays in the audit trail with the reason.

03 · alphaDecide what matters

Ranks each finding by how exposed it is and how long the data must stay secret, and says what to replace it with.

Running it

Run it where your code already is

One command and one runtime dependency, on Windows, macOS and Linux. It opens network connections only to the endpoints you name.

On a laptop

Python 3.11 or newer.

wolfpack scan ./payments-api

In a container

Mount the folder; the results land beside it.

docker run --rm \
  -v "$PWD:/scan" wolfpack

In GitHub Actions

Findings show up as code scanning alerts, and the build can stop on new problems.

with:
  fail-on: critical

Set it up once

A .wolfpack.toml in the repository keeps every run the same: what to skip, when to fail the build, which servers to probe, and how long your data must stay secret.

Against a baseline, only cryptography added since the last release fails the build, so an existing backlog does not block every merge.

exclude    = ["generated", "*.min.js"]
fail_on    = "high"
shelf_life = 15     # years the data stays secret
migration  = 6      # years your migration takes
tls        = ["api.example.com:443"]

Limits

Good to know

Every finding carries its evidence and a confidence, so you can see why it is there. These are the cases where you should look twice.

  • Python is fully parsed. Other languages use rules, so algorithm names built at runtime or passed between functions can be missed.
  • An algorithm found in a binary is built into it, which does not always mean it is used.
  • Container images and cloud key management settings are not scanned.
  • The year a quantum computer could break RSA is an assumption you set, 2035 by default, not a prediction.
